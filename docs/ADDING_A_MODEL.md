# Adding an evaluation model

> **Qué es:** Guía para añadir un modelo de evaluación y compararlo con los demás.
>
> **Cuándo leerla:** Cuando quieras entrenar y medir un modelo nuevo.
>
> **Siguiente paso:** [Models history](training/MODELS_HISTORY.md)

An evaluation model answers one question: *how good is this position for White, as Stockfish
would see it?* The search uses the answer as its evaluation function. Models are compared in the
expected-score scale (win probability), at equal time per move, by the tools below.

## The linear models (current flow)

A linear model is a sparse feature set and a logistic output. Adding one takes two small classes
in `src/chess_engine/models/linear_features.py` and `linear_eval.py`:

1. a `LinearFeatures` subclass with a `name`, `size(perspective)` (number of weights) and
   `active(board, perspective)`, which returns the indices and values of the active features of a
   position (`PstFeatures` and `MaterialCountFeatures` are complete examples);
2. a `LinearEvalModel` subclass registered by name, which points at the feature set:

```python
@register_model("my_model")
class MyModel(LinearEvalModel):
    """One-line description."""

    features = MyFeatures()
    architecture = "One-line description for the card"
```

Then run the flow. Each command works on one model; `scripts/run_all.sh` runs the whole flow.

```bash
# sidecars (split, quiet flag, side to move) for the raw Lichess shards in data/lichess/raw
python scripts/data/prepare_dataset.py --raw data/lichess/raw --out data/lichess/sidecar

# train at an effort level 0-100 (positions, epochs and hyper-parameter trials grow with it)
python -m chess_engine.training.train --model my_model --effort 40

# judge on the fixed test sample: accuracy (Spearman, MAE, best-move agreement) and cost
python -m chess_engine.comparison.evaluate --model my_model

# depth reached and search agreement at a fixed time per move, against the reference bots
python scripts/bench/profile_tradeoff.py --players my_model,h1 --seconds 1,3,10

# round-robin at equal time per move; must include h1 (the Elo anchor)
python scripts/bench/run_tournament.py --players my_model,h1,linear_pst
```

`train` prints the chosen configuration and an estimated duration before it starts. The target
scale is set with `--representation`: `default`, or a JSON object with the fields of
`Representation` (see `training/representation.py`).
Retraining a model overwrites its card (`models/cards/<name>.json`): there is one entry per
approach. The table in `docs/training/MODELS_HISTORY.md` is regenerated by
`python -m chess_engine.comparison.report`.

Once a model has a saved file, a bot can use it:
`python main.py --player1 IterativeModelBookBot --model my_model --player2 IterativeHeuristicBot --depth 2`.

## The CSV-era models (older flow)

`mlp_features` and `cnn_resnet` predate the linear flow. They take
an `EvaluationModel` subclass that chooses an extractor from `models/features.py` and builds a
Keras network (`models/keras_model.py`). They
train from a CSV of Stockfish evaluations and are benchmarked with the centipawn metrics:

```bash
python -m chess_engine.training.train    --model <name> --data data/evaluations.csv
python -m chess_engine.comparison.evaluate --model <name> --data data/evaluations.csv
```

Their current weights are only measured now (accuracy and cost); they are not retrained.

## The contract

| Piece | Where | What it is |
|---|---|---|
| Feature set | `models/linear_features.py` (or `models/features.py`) | turns a board into what the model consumes |
| Model class | `models/linear_eval.py` (or `models/*.py`) | `EvaluationModel` with `predict_cp`, `expected_score`, `fit`, `save`, `load` |
| Registration | `@register_model("name")` | makes it available to the CLIs and the bots by name |
| Card | `models/cards/<name>.json` | what is known about the model; written by the commands |
